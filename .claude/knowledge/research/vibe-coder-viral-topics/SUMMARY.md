# 종합 판정: 유명세를 제거한 바이브 코더 주제

## 수정된 결론

유명 인물·기업 계정을 제외하고 채널 평소 조회수 대비 초과 성과로 다시 보면, 가장 강한 주제는 다음 두 가지다.

1. **Vibe coding의 함정:** 빨리 만든 코드가 왜 진짜 제품이 되지 못하는가.
2. **Agentic engineering의 실제 운영법:** 여러 에이전트를 어떻게 나누고, 관찰하고, 검증하는가.

`10분 음성 램블`과 `AI 빌더 5유형`은 흥미롭지만 현재 데이터로는 Karpathy·Boris Cherny의 저자 효과를 분리할 수 없다. 따라서 제품 근거가 아니라 후속 검증 가설로 강등한다.

## 지금 만들 가치가 있는 제품

### 1. Vibe-to-Real Doctor

사용자가 저장소나 배포 URL을 넣으면 AI가 코드를 칭찬하지 않고 `진짜 사용자가 들어왔을 때 가장 먼저 터질 세 가지`를 찾는다.

- 검사: auth, DB, 권한, 개인정보, 결제, 오류 복구, 비용, 테스트, 분석 이벤트
- 결과: 위험 근거, 재현 방법, 바로 실행할 수정 티켓
- 반복 이유: 기능 추가와 출시 전마다 재검사
- 결제 이유: 장애·보안·재작업의 실패 비용을 줄임
- 바이럴 장치: 공개 가능한 `Prototype 82 → Product 31` 점수와 수정 전후 카드

### 2. Agent Control Room

Codex·Claude Code 세션과 작업 티켓을 읽어 어느 에이전트가 무엇을 하는지, 어디서 컨텍스트가 갈라졌는지, 어떤 결과가 검증되지 않았는지 보여준다.

- 핵심: 작업 분해, 병렬 진행, 컨텍스트 인계, 테스트 통과, 비용
- 결과: 완료 보고가 아니라 `증거가 있는 완료`만 표시
- 반복 이유: AI로 개발하는 매 세션
- 위험: 이미 agent harness가 빠르게 기능을 흡수한다. 특정 도구용 UI보다 검증 규칙과 실행 이력을 자산으로 가져야 한다.

## 현재 Idea Lab에 주는 의미

현재 확인된 유기적 욕구는 `아이디어를 더 달라`가 아니라 **내가 만든 것이 괜찮은지 냉정하게 판정해 달라**에 가깝다.

따라서 다음 실험은 음성 입력으로 바로 피벗하기보다, 현재 결과 뒤에 아래 한 화면을 붙이는 편이 근거가 강하다.

> 이 아이디어를 바이브 코딩하면 어디서 실패할까요?

결과는 추상 카드가 아니라 다음 세 줄이어야 한다.

1. 가장 위험한 가정
2. 프로토타입이 진짜 제품이 되기 전에 필요한 한 가지
3. 이번 주 검증할 실제 행동

## 다음 검증

두 콘텐츠를 같은 무명 계정, 같은 길이, 같은 썸네일 구조로 광고 집행해 비교한다.

- A: `바이브 코딩한 앱이 진짜 제품이 되지 못하는 7가지 이유`
- B: `혼자서 AI 에이전트 5명을 굴리는 실제 작업판`

유명인 리포스트를 배제하고 저장률, 프로필 클릭률, `내 저장소도 검사하고 싶다` 또는 `내 작업도 연결하고 싶다` 전환을 본다. 승자가 다음 제품 가설이다.
