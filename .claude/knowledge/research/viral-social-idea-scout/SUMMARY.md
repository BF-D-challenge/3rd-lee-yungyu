# 판정과 권장 제품 구조

## 결론

독립 제품으로 전면 피벗하는 것은 권하지 않는다. 현재 Idea Lab 앞에 **Trend Scout**라는 새로운 원천 발견 모드를 붙이는 편이 더 강하다.

바이럴은 사람들이 멈춰 본 **관심 신호**이지, 문제·반복 행동·지불 의사의 증거가 아니다. 반대로 현재 앱은 실제 사용·결제 근거가 있는 원본, 돈 낼 사람, 문제가 터지는 순간, 한 끗 변화를 결합하고 제작 프롬프트까지 만든다. 새 기능은 현재 앱이 약한 최신성·발견성을 보완하지만, 현재의 증거 게이트를 대체하면 안 된다.

## 현재 앱과 새 방향 비교

| 기준 | 현재 Idea Lab | 바이럴 게시물 기반 제품 | 권장 결합형 |
|---|---|---|---|
| 시작점 | 검수된 제품 원본 | 급상승 영상·게시물 | 급상승 콘텐츠를 증거 후보로 수집 |
| 사용자 기대 | 만들 만한 제품 아이디어 | 지금 뜨는 것에서 영감 | 지금 뜨는 신호를 만들 만한 제품으로 변환 |
| 강점 | 근거, 구조, 제작 가능성 | 최신성, 재미, 반복 방문 | 최신성과 실행 가능성을 함께 제공 |
| 약점 | 원천이 정적이고 발견 과정이 안 보임 | 유행 추종, 복제, 허위 양성 | 증거 게이트 때문에 속도는 조금 느림 |
| 결과 | 아이디어·코딩 프롬프트·이미지 프롬프트·브리프 | 보통 훅·스크립트·콘텐츠 아이디어 | 출처 영수증이 붙은 제품 아이디어와 7일 MVP |
| 반복 이유 | 다른 조합 뽑기 | 매일 새 트렌드 | 새 신호 확인 → 선택 → 제작 시작 |
| 플랫폼 위험 | 낮음 | 높음 | URL 붙여넣기·수동 큐레이션으로 제한 |
| 핵심 성공 지표 | 결과 완성/복사보다 실제 제작 시작 | 저장·조회·스크립트 생성 | 신호 선택 후 24시간 내 첫 제작 행동 |

## 권장 사용자 흐름

1. **오늘의 신호**: 특정 분야에서 기준 채널 대비 이례적으로 반응한 콘텐츠 한 건을 보여준다.
2. **왜 퍼졌나**: 훅·형식·감정·댓글의 반복 표현을 사실과 해석으로 나눠 보여준다.
3. **증거 게이트**: 관심만 있는지, 실제 불편·우회 행동·구매·도구 사용이 함께 보이는지 판정한다.
4. **현재 네 장 카드로 인계**: 원천 → 돈 낼 사람 → 필요한 순간 → 한 끗을 사용자가 직접 완성한다.
5. **제작 결과**: 현재의 AI 코딩 프롬프트·이미지 프롬프트·전체 브리프를 유지하고, 바이럴 원문과 추출 근거를 덧붙인다.
6. **다음 행동**: 공유보다 `오늘 만들기 시작`을 첫 CTA로 둔다.

## 바이럴 신호를 제품 근거로 승격하는 조건

- 채널의 평소 성과 대비 얼마나 이례적인가: 절대 조회수보다 outlier 배수를 우선한다.
- 댓글에 `원한다`, `어떻게 하냐`, `매번 불편하다`, `지금은 이렇게 대신한다` 같은 반복 행동이 있는가.
- 영상의 재미가 아니라 입력 → 처리 → 결과로 재사용할 수 있는 메커니즘이 있는가.
- 앱·서비스·구매·유료 작업처럼 독립된 사용 또는 지불 근거가 하나 더 있는가.
- 저작물의 표현을 복제하지 않고 문제·메커니즘만 추상화할 수 있는가.

위 조건을 통과하지 못하면 `제품 아이디어`가 아니라 `콘텐츠 영감`으로만 표시한다.

## 가장 작은 검증

### 범위

- 플랫폼: YouTube 하나
- 분야: 한 가지, 예를 들어 `한국 1인 AI 빌더`
- 수집: 자동 크롤링 대신 운영자가 30개 URL을 수동 큐레이션
- 제품: 오늘의 신호 1개 → 현재 네 카드 → 결과 1개
- 기간: 7일

### 성공 판정

- 10명의 목표 사용자 중 5명이 신호를 골라 네 장을 완성한다.
- 3명이 제작 프롬프트를 복사하는 데서 끝나지 않고 실제 빌드 링크·스크린샷·커밋 중 하나를 남긴다.
- 최소 2명이 다음 신호를 보기 위해 7일 안에 다시 온다.

좋아요·공유·“재밌다”는 핵심 검증으로 세지 않는다.
