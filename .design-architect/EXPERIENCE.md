# Experience Contract

플랫폼: responsive-web
전체 여정: 광고 → 독립 예약 페이지 → 예약 입력 → 연락 동의·Google 로그인 → DB 저장 → 완료
현재 작업 범위: 공통 예약 화면, 인증 복귀 상태, Supabase 예약 계약과 검증. 실제 제품 체험은 추후 제공하며 현재 예약 화면에서 연결하지 않음

## 핵심 단계

| 단계 | 진입 조건 | 사용자의 질문 | 주 행동 | 실제 결과 | 실패·회복 |
|---|---|---|---|---|---|
| 1 | 광고 CTA | 무엇을 예약하나 | 예약 페이지 확인 | 제품 약속, 아직 준비 중인 상태, 예약 조건 확인 | 브라우저 뒤로 가기로 광고 유입 경로 복귀 |
| 2 | 맛핀·한입코치 | 어디로 안내받나 | Instagram 아이디 입력 | 정규화·형식 검증 | 필드에서 바로 수정 |
| 3 | 모든 제품 | 언제 써보나 | 희망 시점 선택 | 슬롯 선택 유지 | 기본값으로 이번 주 제공 |
| 4 | 모든 제품 | 어떻게 연락받나 | 연락 동의 후 Google 로그인 | 인증 계정과 예약 연결 | OAuth 복귀 후 동의·입력 복원 |
| 5 | 인증 완료 | 실제로 저장됐나 | 예약 저장 | Supabase 행 또는 명시적 로컬 데모 저장 | 오류 안내 후 재시도 |

## 요청 시점

- 가입: 저장 직전 Google 로그인만 요청
- 권한: 연락 동의 체크 후 로그인 버튼 활성화
- 결제: 없음
- 각 요청 전에 사용자가 이미 얻은 가치: 제품 약속, 필요한 입력, 희망 시점과 개인정보 사용 목적을 모두 확인

## 인터랙션 계약

| 표시 이름 | 종류 | 실제 행동·경로 | 성공 | 실패·취소 |
|---|---|---|---|---|
| 체험 희망 시기 | 라디오 | 한 슬롯 선택 | 선택 강조 | 다른 슬롯 재선택 |
| 연락 동의 | 체크박스 | 동의 시각·문서 버전 임시 저장 | 로그인 활성화 | 해제 시 로그인 비활성화 |
| Google로 예약 계속하기 | 인증 | OAuth 후 같은 예약 주소 복귀 | 계정 확인 상태 | 오류 메시지 후 재시도 |
| 예약 확정 | 쓰기 | 사용자·제품 기준 upsert | 완료 요약 | 저장 실패 안내 후 재시도 |

## 데이터 계약

- 실제 API 또는 교체 가능한 Mock API: Supabase Auth·Postgres, 미연결 환경은 localStorage 데모
- loading: 계정 확인 중·저장 중을 텍스트와 상태 아이콘으로 표시
- empty: 기존 예약이 없으면 입력 흐름 표시
- error: 인증 상태·예약 저장 실패를 화면 안에서 설명하고 재시도 허용
- partial·permission: Supabase 연결 시 인증 사용자 본인 행만 RLS로 SELECT·INSERT·UPDATE
- 쓰기 성공·중복·rollback: `(user_id, product)` upsert, 성공 응답 검증 뒤 완료 전환, 실패 시 입력 유지

## 맛핀 Instagram 여정

| 단계 | 진입 조건 | 주 행동 | 실제 결과 | 실패·회복 |
|---|---|---|---|---|
| 1 | 맛집 릴스 시청 | `matpin.kr` 계정으로 공유 | Meta Webhook이 서명된 메시지만 큐에 저장 | 미지원 첨부는 저장하지 않고 안내 |
| 2 | 분석 가능한 릴스 확보 | 기다림 | Gemini가 캡션 → 작성자 댓글 → 영상 순서로 직접 확인되는 장소 단서를 구조화 | 키 없음·타임아웃·근거 부족은 명시적 실패 |
| 3 | 장소 단서 존재 | 장소 검색 | 카카오 키가 있으면 카카오, 없으면 Gemini의 Google Maps 근거로 실제 장소 후보 최대 3개 생성 | 지도 근거가 없는 단서는 저장하지 않음 |
| 4 | 지도 근거가 있는 후보 1~3개 | 자동 저장 | 한 릴스의 모든 후보를 발신자 scoped ID에 저장하고 가까운 역으로 분류 | 같은 릴스·같은 장소 중복은 한 항목으로 유지 |
| 5 | Instagram 답장 링크 | 역별 보관함 열기 | 역 선택·영상 탐색·원본 릴스·길찾기·삭제 제공 | 만료·잘못된 링크는 최신 DM 링크 재요청 |

- 토큰은 URL fragment로 전달해 서버 요청 로그와 외부 리퍼러에 포함하지 않는다.
- Meta 발신자 ID와 임시 미디어 URL은 암호화하고, 분석 완료 또는 최종 실패 뒤 미디어 URL을 제거한다.
- 개인 보관함 링크는 마지막 릴스 수신 후 90일 동안 유효하며 새 릴스를 보내면 갱신한다.
- 역별 보관함에서 장소 하나를 지우거나 `내 데이터 관리`에서 계정 연결 정보와 하위 데이터를 한 번에 삭제할 수 있다.
- 맛핀은 현재 위치 권한을 요청하지 않으며, 가까운 역은 저장 장소의 실제 주소와 좌표로만 계산한다.

### 맛핀 오가닉 공유 여정

전체 여정: 역별 보관함에서 장소 확인 → 장소 1~5곳 선택 → 공개 링크 생성 → 친구가 가입 없이 확인 → 친구가 링크를 `matpin.kr` DM으로 전송 → 친구의 Instagram 계정 보관함에 복사 → 친구가 다시 공유

| 단계 | 진입 조건 | 주 행동 | 실제 결과 | 실패·회복 |
| --- | --- | --- | --- | --- |
| 1 | 역별 보관함에서 장소 상세를 확인 | `같이 갈 곳 보내기` | 현재 장소 1곳이 선택된 공유 시트 | 취소하면 원래 상세로 복귀 |
| 2 | 공유 시트가 열림 | 장소 1~5곳 선택 후 `N곳 링크 만들기` | 선택 장소만 참조하는 공개 shareToken 생성 | 생성 실패 시 선택을 유지하고 재시도 |
| 3 | 공유 링크 생성 성공 | 메시지·링크 복사·OS 공유 | 친구에게 공개 장소 묶음 전달 | 공유 시트 취소 시 링크는 유지 |
| 4 | 친구가 `/s/{shareToken}` 방문 | 장소·지도·릴스 확인 | 가입 전 실제 결과 확인 | 만료·철회는 이유와 새 링크 요청 행동 표시 |
| 5 | 친구가 결과를 확인 | `내 보관함에도 담기` | Instagram 전송 안내 시트 | Web Share 미지원 시 링크 복사·프로필 열기 제공 |
| 6 | 친구가 공개 링크를 `matpin.kr` DM으로 전송 | 기다림 | 친구의 Instagram-scoped ID 보관함에 장소 복사·개인 링크 답장 | 중복은 하나로 유지, 잘못된 토큰은 같은 DM에서 안내 |
| 7 | 친구가 개인 보관함 확인 | 장소 재사용 또는 다시 공유 | 수신자→발신자 루프 완료 | 공유하지 않아도 개인 보관함 기능은 유지 |

- 주요 웹 페이지는 `/matpin`, `/matpin/saved#token=...`, `/s/{shareToken}` 세 개다.
- 공유 장소 선택과 가져오기 안내는 새 페이지가 아니라 바텀시트다.
- 공개 링크에는 개인 보관함 토큰과 공유자의 Instagram 아이디를 포함하지 않는다.
- 공개 링크 철회는 즉시 적용하고, 철회 뒤에는 장소 데이터 대신 종료 상태만 표시한다.
- 이 여정은 설계 상태이며 공개 장소 묶음과 DM 가져오기 계약은 구현 전이다.

## 화면별 추가 여정: 카드너머

전체 여정: 진입 → 익명 타로 덱 이해 → 카드 탭·드래그 → 슬롯 안착·플립 → 랜덤 장면 확인 → 명시적 대화 시작 → 답장 → 선택적 출시 알림 예약

| 단계 | 진입 조건 | 주 행동 | 실제 결과 | 실패·회복 |
|---|---|---|---|---|
| 덱 | 상황 카드 목록 로딩 성공 | 카드 탭·드래그 또는 빈 슬롯 탭 | 같은 뒷면 카드 한 장만 곡선 비행 | 로딩 실패 시 같은 화면에서 다시 불러오기 |
| 공개 | 카드가 슬롯에 도착 | 뒤집힌 장면 읽기 | 네 상황 중 한 장면과 가이드 공개 | 다른 카드 뽑기로 덱 복귀 |
| 시작 | 장면을 읽음 | 이 장면에서 대화 시작 | Mock API 첫 질문과 빠른 답장 | 실패 시 장면을 보존하고 재시도 |
| 대화 | 첫 질문 확인 | 빠른 답장 또는 직접 입력 | 횟수에 맞는 Mock 후속 질문 | 실패 시 사용자가 쓴 문장 복원 |
| 다음 | 세 번 답장 | 선택적 예약 또는 계정 연결 | 예약 흐름 이동, 계정 연결은 선택 | 로그인·결제는 첫 가치 전에 요구하지 않음 |

인터랙션 계약: 부채꼴 덱 진입 스윕, 선택 카드 리프트·드래그 틸트, 260ms 곡선 비행, 안착 팝, 약 280ms 플립과 짧은 블룸. `prefers-reduced-motion`에서는 이동과 플립을 생략해도 같은 결과와 포커스 순서를 유지한다.

## 맛핀 스토리보드 랭킹 여정

전체 여정: 6개 스토리보드 확인 → 보드 확대 → 별점·의견 작성 → 수동 순위 변경 → 통과 후보 선택 → 다음 라운드 → 최종 1위

| 단계 | 진입 조건 | 주 행동 | 실제 결과 | 실패·회복 |
|---|---|---|---|---|
| 1 | `/matpin/storyboard-ranking` 직접 진입 또는 모바일 프레임의 평가 링크 | 후보 4장면 확인·확대 | 같은 제품 사실을 다른 구도로 표현한 6개 보드 비교 | 확대 화면은 닫기·Escape로 복귀 |
| 2 | 후보를 확인함 | 별점·의견 입력 | 후보별 평가가 현재 라운드에 저장 | 글자 수 240자로 제한, 입력은 그대로 유지 |
| 3 | 두 후보 이상 | 순위 올리기·내리기 | 보이는 목록 순서가 곧 수동 랭킹 | 첫 후보의 올리기와 마지막 후보의 내리기는 비활성화 |
| 4 | 다음에 볼 후보를 판단함 | `다음 라운드에 남기기` | 선택 수와 통과 상태 즉시 갱신 | 다시 누르면 선택 취소 |
| 5 | 후보 2개 이상 선택 | `N라운드 시작` | 선택 후보만 다음 라운드에 남고 이전 평가는 기록으로 보존 | `이 라운드 다시 편집`으로 당시 순서·평가 복원 |
| 6 | 후보 1개 선택 | `이 안을 1위로 확정` | 최종 1위 보드 표시 | 마지막 라운드로 돌아가 재선택 가능 |

- 브라우저 새로고침 뒤에도 localStorage에서 현재 라운드와 이전 평가를 복원한다.
- `처음부터`는 확인창 뒤에만 모든 로컬 평가를 지운다.
- 새 시안 자동 생성은 연결하지 않고 화면 하단에 미연결 상태를 명시한다.
- 각 후보는 같은 모바일 과업을 유지하되 `정면·탑뷰·사선·매크로·측면·분할` 중 하나의 시점만 사용한다. 후보 헤더의 Mobbin 링크는 새 탭에서 실제 참조 화면을 연다.
- 820px 이하에서는 4개의 390×844 화면을 카드 내부에서 가로로 넘긴다. 페이지 전체가 가로로 밀리지 않으며 별점·의견·통과 버튼은 세로 흐름에 남는다.
