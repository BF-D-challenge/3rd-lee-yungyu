# 광고 이미지 시스템 v2 — 제품 증거 우선

작성일: 2026-07-26
대상: Meta 모바일 피드 4:5, 1080×1350
상태: 15개 시안 렌더 완료, 문구·집행 승인 전

## 결론

기존 시안의 AI 티는 생성 품질보다 구조의 문제였다.

- 모든 아이디어가 비슷한 그라디언트와 3D 이미지로 보였다.
- 제품이 실제로 무엇을 하는지 보여주는 화면이 없었다.
- 광고 안의 가짜 버튼과 넓은 카피 영역이 랜딩 뒤 행동을 흐렸다.
- 서로 다른 5개 아이디어가 같은 템플릿의 색상 변형처럼 보였다.

v2는 15장 모두 AI 배경을 제거했다. 실제 제품 화면, 보유 카드 자산,
코드로 그린 문구와 도형만 사용한다.

## 사용자 여정 계약

전체 여정:

1. Meta 피드를 보다가 자신의 문제 순간을 발견한다.
2. 광고 안의 실제 제품 화면으로 결과를 미리 확인한다.
3. 광고를 눌러 각 실험 랜딩으로 이동한다.
4. 로그인 없이 첫 입력을 한다.
5. 실제 결과를 본 뒤에만 저장·재사용·가입을 선택한다.

현재 광고의 단계는 `문제 인식 → 구체적 증거 확인`이다. 광고의 첫 목적은
브랜드 설명이 아니라 “이 제품이 내 입력을 어떻게 바꾸는가”를 5초 안에
알려주는 것이다.

| 아이디어 | 광고 뒤 실제 경로 | 첫 입력 | 즉시 결과 | 광고의 예측 문장 |
| --- | --- | --- | --- | --- |
| Tastepin | `/tastepin` | YouTube Shorts 공개 링크 | 장소·메뉴 단서와 지도 후보 | 맛집 쇼츠 링크 붙여보기 |
| Onebite | `/onebite` | 음식 사진 1장 | 다음 끼니의 작은 행동 | 음식 사진 한 장 고르기 |
| Today A | `/today-a` | 불편·고객·강점·시간 | 조건에 맞는 사업 구조 | 내 조건으로 구조 보기 |
| Today B | `/today-b` | 아이디어·고객·약속·채널 | 위험 가정과 7일 실험 | 위험한 가정부터 찾기 |
| Story Cards | `/story-cards` | 랜덤 카드 열기 | 8번 선택하는 이야기 | 로그인 없이 카드 열기 |

광고 이미지 안에는 실제로 누를 수 없는 버튼을 만들지 않는다. 하단 문장은
Meta의 실제 CTA 버튼을 누른 뒤 할 일을 예고하는 행동 라벨이다.

## 5초 인지 계약

| 아이디어 | 가장 먼저 보여야 하는 것 | 이해해야 하는 것 | 느껴야 하는 감정 | 기억 단서 |
| --- | --- | --- | --- | --- |
| Tastepin | 저장한 맛집 영상 문제 | 링크가 장소 단서로 바뀜 | “이건 바로 해볼 수 있겠다” | 살구색 포스터 + 실제 링크 입력 화면 |
| Onebite | 음식 사진 한 장 | 평가보다 다음 행동을 받음 | 안도감 | 분홍 메모 + 실제 업로드 화면 |
| Today A | 내 조건 | 조건이 시작 구조로 바뀜 | 정리되는 느낌 | 민트 형광펜 + 실제 폼 |
| Today B | 위험한 가정 | 만들기 전에 7일로 검증함 | 냉정한 확신 | 어두운 증거 보드 + 보라 선 |
| Story Cards | 랜덤 카드 한 장 | 로그인 없이 대화를 시작함 | 가벼운 호기심 | 실제 실행 화면 + 보유 카드 뒷면 |

정보의 순서는 `문제/결과 문장 → 실제 제품 화면 → 다음 행동`이다.

## 레이어 계약

| 아이디어 | 코드로 적는 글자 | 배치·도형 레이어 | 실제 이미지 레이어 | AI 이미지 |
| --- | --- | --- | --- | --- |
| Tastepin | 헤드라인, 설명, 순간 라벨, 행동 라벨 | 살구 배경, 원형 포인트, 흰 화면 프레임 | `tastepin.jpg` | 현재 15장에는 없음 |
| Onebite | 헤드라인, 옆 메모, 행동 라벨 | 분홍 배경, 메모 탭, 사진 프레임 | `onebite.jpg` | 없음 |
| Today A | 헤드라인, 설명, 결과 라벨 | 종이 배경, 민트 형광펜, 문서 프레임 | `today-a.jpg` | 없음 |
| Today B | 헤드라인, 설명, 가정 라벨 | 검정 보드, 보라 테두리, 증거 패널 | `today-b.jpg` | 없음 |
| Story Cards | 헤드라인, 설명, 카드 라벨 | 따뜻한 테이블색, 화면 프레임 | `story-cards.jpg`, `public/cards/*` | 없음 |

렌더러에서는 HTML/CSS 대신 동일한 역할을 하는 manifest 좌표와 SVG를
사용한다.

- `text`, `pill`: 코드 문구
- `rect`, `circle`, `gradient`: CSS에 해당하는 배치·색·면
- `image`: 실제 파일을 잘라 넣는 이미지 레이어
- `background.fill`: 생성 이미지가 아닌 단색 바탕

문구와 이미지는 한 장으로 합성하기 전까지 분리되어 있다. 문구 변경,
화면 교체, 색상 변경을 이미지 생성 없이 다시 렌더할 수 있다.

## AI 이미지 사용 경계

기본값은 `사용 안 함`이다. 아래 조건을 모두 만족할 때만 보조 이미지로
검토한다.

1. 보유 제품 화면이나 직접 촬영한 사진으로 설명할 수 없다.
2. 결과나 성과의 증거처럼 오해되지 않는다.
3. 사람 얼굴, 손, 앱 UI, 글자를 생성하지 않는다.
4. 전체 면적의 25%를 넘지 않는다.
5. 생성 이미지가 없어도 헤드라인과 제품 화면만으로 광고가 이해된다.

아이디어별 판단:

- Tastepin: 실제 촬영 음식 사진을 확보하면 상단 분위기 컷으로 추가 가능.
  AI 음식은 실제 식당 증거로 오해될 수 있어 사용하지 않는다.
- Onebite: 사용자가 허용한 실제 음식 사진만 사용한다. AI 음식·캐릭터는
  현재 제품 행동을 설명하지 못하므로 제외한다.
- Today A/B: 추상적 비유 이미지가 오히려 판단 흐름을 가리므로 사용하지
  않는다.
- Story Cards: 보유 카드와 제품 화면이 있으므로 새 AI 카드는 만들지 않는다.

## Material 3 적용과 구현 판단

공식 Material 3 자료:

- 시각 계층과 구조:
  <https://m3.material.io/foundations/designing/structure>
- 타이포그래피 적용:
  <https://m3.material.io/styles/typography/applying-type>
- 이미지 위 텍스트 대비:
  <https://m3.material.io/components/cards/guidelines>
- compact 피드 구성:
  <https://m3.material.io/foundations/layout/canonical-examples/feed>

공식 지침에서 가져온 원칙:

- 이미지 위 글자는 충분한 대비가 필요하며 필요하면 별도 면을 둔다.
- compact 화면에서는 한 열로 읽히게 한다.
- 크기·굵기·간격으로 우선순위를 분명하게 만든다.

이번 구현의 판단:

- 문구를 제품 화면 위에 직접 얹지 않고 별도 단색 영역에 둔다.
- 4:5 피드에서 헤드라인, 제품 화면, 행동 라벨을 세로 한 열로 읽게 한다.
- 작은 제품 화면 글자를 읽게 하기보다 화면의 실제 형태를 증거로 보여주고,
  핵심 의미는 큰 코드 문구로 다시 설명한다.

## 모션 판단

현재 산출물은 정적 Meta 이미지다. 상태 변화나 인과를 설명할 필요가 없어
모션을 넣지 않는다. Story/Reels로 확장할 때도 `입력 → 처리 → 결과`의
실제 화면 전환만 사용하고, 장식용 부유·반짝임은 추가하지 않는다.

## 게시 게이트

자동 검사는 다음을 확인한다.

- 1080×1350 출력
- 72px 안전 영역
- 누락된 이미지 파일
- 잘린 텍스트
- 임시 배경 사용 여부
- 각 시안의 승인 상태

현재 결과:

- 15/15 렌더 성공
- 임시 배경 0
- 안전 영역 경고 0
- AI 생성 이미지 0
- `approval.status = draft`이므로 게시 차단

문구와 랜딩 URL을 사람이 확인한 뒤 해당 시안만 `approved`로 바꿔야
게시 게이트가 통과한다.
