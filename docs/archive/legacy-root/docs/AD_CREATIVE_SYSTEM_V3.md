# 광고 이미지 시스템 v3 — 선택 형식 × 제품 USP

작성일: 2026-07-26
대상: Meta 피드 4:5 `1080×1350`, Reels/Stories 9:16 `1080×1920`
상태: 구현 설계 초안. 이미지 생성·촬영·문구·집행 승인 전

## 1. 결정 원칙

이번 15개 변형은 다음 규칙을 고정한다.

1. 성과 신호가 강한 광고에서는 **USP의 표현 우선순위만** 가져온다.
2. 시각 형식과 레이어 구조는 사용자가 선택한 `U1~U20`만 사용한다.
3. 경쟁사 이미지·문구·캐릭터는 최종 소재에 넣지 않는다.
4. 제품 화면과 실제 데이터는 증거이고, AI 이미지는 세계관·은유·캐릭터다.
5. AI로 UI·글자·영수증·정산 내역·실제 사람을 만들지 않는다.
6. Meta의 실제 CTA 버튼처럼 보이는 가짜 버튼을 이미지 안에 그리지 않는다.
7. 레퍼런스에 없는 카드·배지·제품 화면은 정보가 중요해도 광고 이미지에 추가하지 않는다.
8. 먼저 `큰 시각 덩어리 수 / 미디어 점유율 / 제목 위치 / 겹침 순서`를 맞춘다.

```text
메시지 우선순위 = 검증된 제품 USP
형식 = U1~U20 사용자 선택 레퍼런스
증거 = 실제 제품 화면·실제 촬영·검증 가능한 데이터
분위기 = 통제된 AI 이미지
글자 = 코드 렌더링
배치 = manifest/CSS 레이어
```

## 2. 사용자 여정과 데이터 계약

광고의 현재 단계는 `피드에서 문제 발견 → 제품 결과를 미리 이해 → 실제 첫 입력`이다.

| 제품 | 랜딩 | 첫 입력 | API | 즉시 결과 | 광고 행동 라벨 |
| --- | --- | --- | --- | --- | --- |
| Tastepin | `/tastepin` | YouTube Shorts 공개 URL | `POST /api/tastepin/resolve` | 영상에서 확인한 장소·메뉴 단서, Kakao 지도 후보 | 맛집 쇼츠 링크 붙여보기 |
| Onebite | `/onebite` | 음식 사진 1장 | `POST /api/onebite/analyze` | 사진에서 직접 보이는 그룹과 다음 끼니 행동 한 가지 | 음식 사진 한 장 고르기 |
| Today A | `/today-a` | 문제·고객·강점·주간 시간 | `POST /api/today-a/structure` | 검증 원본에 기반한 시작 구조와 첫 제안 | 내 조건으로 구조 보기 |
| Today B | `/today-b` | 아이디어·고객·약속·채널·행동 신호 | `POST /api/today-b/experiment` | 가장 위험한 가정과 7일 실험 | 위험한 가정부터 찾기 |
| Story Cards | `/story-cards` | 상황 카드 한 장 선택 | `GET/POST /api/story-cards` | 가이드의 첫 질문과 선택지 | 로그인 없이 카드 열기 |

광고 문구는 API가 실제로 반환하지 않는 결과를 약속하지 않는다.

- Tastepin은 영상에서 식당명을 직접 확인하지 못하면 `insufficient`를 반환할 수 있다.
- Onebite는 칼로리·체중·외모·진단을 말하지 않고 행동 한 가지만 제안한다.
- Today A의 근거는 저장된 감사 통과 스냅샷이며 실시간 성과가 아니다.
- Today B는 `rule_based_mock`이며 실제 수요나 성공을 예측하지 않는다.
- Story Cards는 현재 `mock` 상황·대화 API다.

공통 렌더 조건:

- 4:5 안전 영역: 상하좌우 `72px`.
- 9:16 안전 영역: 좌우 `72px`, 상단 `160px`, 하단 `280px`.
- 제목은 Pretendard 또는 기존 제품 한글 폰트, 다중 행 line-height `1.30~1.38`.
- 본문 line-height `1.50~1.60`, 표·목록 `1.45` 이상.
- 이미지 위 텍스트는 독립된 면 또는 55~75% 스크림 위에 둔다.
- 모든 코드 문구는 이미지 생성과 분리해 재렌더 가능해야 한다.

### 3.1 Z축 합성 계약

모든 변형은 화면을 상·중·하단으로 완전히 나누지 않고 **한 기준점 위에 오브젝트를
차례로 쌓아 올린 합성 포스터**로 구현한다. `Grid/Flex`는 레이어의 내부 정렬에만 쓰고,
광고의 주 구성은 동일한 `position: relative` 캔버스 위 절대 배치로 만든다. 각 레이어는
공중에 흩어져 떠 있지 않고 아래 레이어에 닿거나 기대며, 아래쪽 모서리가 일부 보여야 한다.

| 깊이 | 레이어 | 역할 | 구현 |
| ---: | --- | --- | --- |
| `z0` | `base` | 캔버스 전체의 색·질감·실사 원본 | full-bleed, `inset: 0` |
| `z1` | `ai-art` | 세계관·캐릭터·은유, 또는 실사 뒤의 확장 배경 | full-bleed 또는 캔버스 55~100% |
| `z2` | `product-evidence` | 실제 제품 화면·결과·촬영 피사체 | cutout/mask 후 AI·배경 위에 부상 |
| `z3` | `bridge` | 깊이를 잇는 그림자·스크림·빛·핀·화살표 | 앞뒤 레이어 양쪽을 일부 침범 |
| `z4` | `code-text` | 제목·표·수치·고지 | 피사체의 빈 공간 또는 스크림 위 |
| `z5` | `cta/legal` | 행동 라벨·필수 고지 | 안전 영역 안의 최전경 |

필수 겹침 규칙:

- 하나의 `stackAnchor`를 정하고 `z1 → z2 → z3 → z4 → z5`가 같은 대각선 또는
  수직 축을 따라 위로 쌓인다. 서로 무관한 여러 섬으로 분산하지 않는다.
- 주요 `z1`과 `z2` 경계는 캔버스 짧은 변 기준 `12~24%` 겹친다.
- 카드·제품 화면처럼 단단한 레이어는 바로 아래 레이어의 모서리를 `24~64px` 남기고
  덮는다. 모든 하단 레이어가 최소 한 군데는 보여야 한다.
- 앞 레이어일수록 그림자 거리와 선명도가 커지고, 뒤 레이어는 대비와 초점이 낮아진다.
  그림자 방향은 하나의 주광원과 일치시킨다.
- 회전은 뒤에서 앞으로 `-4deg → -2deg → 1deg → 3deg`처럼 작은 차이만 두고,
  인접 레이어가 같은 각도로 평평하게 겹치지 않게 한다.
- 제목은 배경/피사체 외곽을 시각적으로 덮되 얼굴·핵심 결과·식별 수치는 가리지 않는다.
- 제품 화면은 별도 하단 띠가 아니라, 회전 `-4~4deg`·마스크·원근을 가진 전경 오브젝트로 둔다.
- 비교표와 TOP 목록도 별도 패널로 완전히 분리하지 않고 주 피사체 앞뒤로 일부 가린다.
- 두 레이어 사이에 빈 gutter나 수평 분할선을 두지 않는다. 깊이 차이는 겹침, 크기,
  초점, 그림자, 스크림으로 표현한다.
- 텍스트가 이미지 위에 놓일 때는 M3의 이미지 위 텍스트 대비 지침에 따라 55~75% 국소
  스크림 또는 충분한 음영 여백을 사용한다. 생성 이미지 안에 텍스트를 굽지 않는다.
- 동일 장면의 AI·실사·제품 화면은 색온도와 주광원 방향을 맞추고, 최종 합성에서 같은
  grain을 한 번만 적용한다.

선택 레퍼런스가 full-bleed 인물이나 한 장의 편집 포스터일 때는 여러 제품 카드를
의무적으로 추가하지 않는다. 이 경우 `z1 full-bleed media → z3 국소 스크림 →
z4 코드 문구 → z5 고지`가 유효한 z축 스택이다. 한 장의 AI 장면 안에서 같은 캐릭터의
낮·밤을 대각선으로 겹치는 것은 허용하지만, UI를 상단·하단 섹션으로 나누는 분할
레이아웃은 계속 금지한다.

### 3.1.1 레퍼런스 충실도 게이트

- 160px 축소본과 12px blur에서 레퍼런스와 첫 번째·두 번째 시각 덩어리 순서가 같아야 한다.
- 주 미디어 점유율은 레퍼런스 대비 `±10%p`, 제목 점유율은 `±8%p` 안에서 시작한다.
- 레퍼런스에 없는 둥근 면은 기본값 `0개`다. 필요한 제품 고지나 행동 라벨만 예외로 남긴다.
- 픽셀 유사도는 사전 점검으로만 쓰고, 패널 수·대각선·PIP·제목 위치 같은 형식 규칙을
  더 높은 우선순위로 판정한다.
- 두 Story Cards 소규모 테스트의 근거와 결과는
  `docs/AD_REFERENCE_FIDELITY_LAB_2026-07-26.md`에 기록했다.

```css
.ad-canvas { position: relative; isolation: isolate; overflow: hidden; }
.ad-layer { position: absolute; pointer-events: none; }
.ad-base { z-index: 0; inset: 0; }
.ad-ai { z-index: 10; inset: 0; }
.ad-evidence { z-index: 20; }
.ad-bridge { z-index: 30; inset: 0; }
.ad-copy { z-index: 40; }
.ad-cta { z-index: 50; }
```

레이어 위치는 픽셀을 각 변형에 직접 박지 않고 아래 데이터로 저장한다.

```json
{
  "stackAnchor": { "x": 0.54, "y": 0.56 },
  "layers": [
    { "id": "world", "z": 10, "offset": [0, -0.08], "scale": 1.08, "rotate": -4 },
    { "id": "evidenceBack", "z": 20, "offset": [-0.05, 0.01], "scale": 0.82, "rotate": -2 },
    { "id": "evidenceFront", "z": 24, "offset": [0.06, 0.08], "scale": 0.76, "rotate": 2 },
    { "id": "copy", "z": 40, "offset": [-0.18, -0.23], "scale": 1, "rotate": 0 },
    { "id": "cta", "z": 50, "offset": [0.13, 0.27], "scale": 1, "rotate": 0 }
  ]
}
```

### 3.2 Instagram placement 파생 규칙

2026-07-26에 확인한 Meta 공식 가이드는 Feed에 `4:5`, Stories와 Reels에 `9:16`을
권장하고, 사진은 `1:1` 또는 `4:5`, Reels는 최소 `30fps`·`720px`을 요구한다. Reels는
핵심 메시지를 safe zone에 둘 것을 안내하지만 고정 px 수치는 화면 UI와 계정 상태에 따라
달라질 수 있으므로, 최종 업로드 전 Meta의 Reels safe-zone checker와 Ads Manager
placement preview를 통과시킨다.

공식 근거:

- [Meta Tailored Campaigns — Feed 4:5, Stories/Reels 9:16](https://www.facebook.com/business/ads/automation/tailored-campaigns)
- [Meta Reels ads — 9:16, audio, key messages in safe zone](https://www.facebook.com/business/ads/facebook-instagram-reels-ads)
- [Instagram Reel size — 30fps, minimum 720px](https://www.facebook.com/help/1038071743007909)
- [Instagram ads — Feed, Stories, Explore formats](https://www.facebook.com/business/ads/instagram-ad)

| placement profile | 출력 | 내부 안전영역 | 스택 재구성 |
| --- | --- | --- | --- |
| `ig_feed_portrait` | `1080×1350`, 4:5 | 사방 `72px` | 기본. 더미가 화면 중앙 80%를 채움 |
| `ig_feed_square` | `1080×1080`, 1:1 | 사방 `72px` | 같은 더미를 `0.86~0.9×` 축소하고 CTA를 위로 이동 |
| `ig_explore_feed` | `1080×1350`, 4:5 | 사방 `72px` | Feed와 같은 자산, 첫 시선 피사체를 중앙에 유지 |
| `ig_carousel_square` | `1080×1080`, 1:1 | 사방 `72px` | 장마다 스택 1개. 다음 장에 이어지는 잘린 모서리 허용 |
| `ig_story` | `1080×1920`, 9:16 | 좌우 `72px`, 상단 `180px`, 하단 `300px` | 배경을 위아래로 확장하고 더미를 중앙보다 4% 위로 |
| `ig_reels` | `1080×1920`, 9:16 | 좌 `72px`, 우 `160px`, 상단 `180px`, 하단 `360px` | 우측 반응 UI를 피해 더미 중심을 `x=0.46`으로 이동 |
| `ig_reels_cover` | `420×654`, 약 1:1.55 | 중앙 80% | 광고 집행본이 아닌 프로필/부스트 준비용 별도 cover |

위 px 안전영역은 **공식 고정값이 아니라 이 시스템의 보수적 제작값**이다. UI 변화에
대응하기 위해 `config/ad-image/placement-profiles.v3.json`에서 수정하며, 최종 확인은
Ads Manager의 placement asset customization 화면에서 한다.

한 개의 원본을 단순 자동 crop하지 않는다.

1. `1080×1920` 마스터에서 배경 `z0~z1`은 full-bleed로 만든다.
2. 모든 필수 정보는 중앙 4:5 공통 corridor `x 72~1008 / y 285~1635` 안에 먼저 둔다.
3. Feed·Square·Stories·Reels마다 `stackAnchor`, scale, CTA 위치만 재배치한다.
4. 레이어의 z-order와 겹침 관계는 모든 placement에서 동일하게 유지한다.
5. Reels/Stories의 위아래 확장은 AI 배경 또는 실사 여백만 사용하고 제품 UI를 늘리지 않는다.
6. Feed/Explore 정지본과 Reels/Stories 영상본은 같은 첫 프레임을 사용해 캠페인 기억을 잇는다.

## 4. 15개 광고 변형

- 제품 증거: 실제 상황 제목·첫 질문을 API 데이터에서 가져온다.
- 랜딩: `/story-cards`.

### Story Cards 02 — 실사 × AI 메이킹 필름

- 형식 레퍼런스: `U6 실사와 AI 세계 연결`, `U20 QWER 메이킹`.
- USP: 생성된 세계만 보여주지 않고 카드가 기획·검수되고 실제 대화로 연결되는 과정을 보여준다.
- 9:16 흐름: `0~2초 카드 스케치 → 2~5초 AI 아트 생성 → 5~8초 실제 화면 검수 → 8~11초 첫 대화`.
- AI 이미지: 카드 배경과 가이드 캐릭터. 생성 전/후를 구분해 표시.
- 코드 텍스트: `MAKING STORY CARD` / `그림보다 먼저, 첫 질문을 검수합니다`.
- CSS/Z축: 제작자 손과 작업대를 full-bleed로 촬영한다. AI 카드가 종이 스케치에서
  솟아오르는 전경 cutout으로 겹치고, 실제 실행 화면이 그 카드를 일부 가리며 handoff한다.
- 실제 촬영: 프롬프트 초안, 카드 검수표, 휴대폰 실제 실행, 제작자 손.
- 제품 증거: `/story-cards` 시작 응답과 첫 질문.
- 랜딩: `/story-cards`.

### Story Cards 03 — 오늘 밤 대화 TOP 3

- 형식 레퍼런스: `U11 Bloom TOP 3`, `U7 선택지`, `U17 밈형 말풍선`.
- USP: 네 상황 중 한 장을 고르고 첫 질문으로 대화를 시작한다.
- 4:5 인지 순서: `감정 장면 → 상황 TOP 3 → 한 장 선택`.
- AI 이미지: 오리지널 가이드 1명과 장면 3개를 같은 화풍·광원·카메라로 생성.
- 코드 텍스트:
  - `오늘 밤 말이 필요할 때`
  - `대화가 시작되는 상황 TOP 3`
  - `전하지 못한 말 / 놓친 기회 / 조용히 털어놓기`
  - 행동 라벨 `첫 카드 한 장 열기 →`
- CSS/Z축: 가이드를 중앙 후경에 두고 장면 3개를 좌우 원근 레이어로 겹친다. 선택지
  3행과 말풍선은 장면의 빈 공간을 타고 앞뒤로 교차하며 실제 카드 제목이 최전경에 온다.
- 실제 촬영: 없음.
- 제품 증거: 실제 상황 카드 제목과 kicker.
- 랜딩: `/story-cards`.
