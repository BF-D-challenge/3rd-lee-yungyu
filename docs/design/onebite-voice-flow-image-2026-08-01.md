# 한입코치 음성 팩폭 5화면 계약

## Product Truth

- 사용자: 식단 기록은 오래 못 하지만, 흔들린 한 끼 뒤 다음 끼니에는 복귀하고 싶은 20~30대 직장인
- 문제: 숫자와 점잖은 조언은 넘겨버리고, 망한 한 끼를 망한 하루로 키운다.
- 입력: 음식 사진 한 장과 재방문 시 지난 행동의 실행 여부
- 처리: 서버가 사진을 축소·메타데이터 제거 후 Gemini에 한 번 보내 음식 이름·그룹, 안전한 코미디 팩폭 문장, 다음 행동 코드를 받는다. 안전 필터를 통과한 문장은 사용자가 재생을 누를 때 기기의 한국어 음성으로 읽는다.
- 결과: 사진 기준 예상 칼로리 범위, 사진 속 음식만 놀리는 음성 팩폭, 실제 트레이너가 권할 만한 다음 끼니 행동 하나
- 가치 순간: 사용자가 예상 칼로리와 사진 전용 팩폭을 음성으로 듣고, 바로 실행할 복귀 행동까지 이해하는 순간
- 주 행동: `다음 한입 받기`
- primary metric: 분석 성공 사용자 중 음성 팩폭 재생 후 복귀 행동을 저장한 비율
- guardrail: 자동 재생 0건, 몸·체중·외모·인격 공격 0건, TTS 미지원 시 대사 보기 제공, 사진 저장 0건
- 범위 밖: 사진만으로 정확한 칼로리·중량 단정, 질환 판단, 음성 파일 서버 저장, 실제 사람 목소리 복제, 자동 결제

## 실제 처리 계약

- 근거 입력: 사용자가 직접 고른 JPG·PNG·WebP 음식 사진 최대 5MB
- 모델 처리: 목표 계약은 기존 `visibleFoods`, `visibleGroups`, `confidence`, `riskFlag`, `roastLine`, 서버 고정 `actionLine`에 `estimatedCalories`를 추가한다. 현재 API에는 아직 칼로리 필드가 없으므로 craft 단계에서 schema와 검증을 먼저 구현해야 한다.
- 칼로리 계약: `estimatedCalories`는 단일 정답이 아니라 `minKcal`, `maxKcal`, `assumptions`, `confidence`를 반환한다. 화면에는 `사진 기준 예상 900~1,150 kcal`처럼 범위로 표시하고 `양·조리법에 따라 달라져요`를 붙인다.
- 음성 처리: 1차 구현은 브라우저 `speechSynthesis`와 사용 가능한 `ko-KR` 음성을 사용한다. 자동 재생하지 않고 사용자 탭 뒤에만 재생한다. 읽는 순서는 `예상 칼로리 → roastLine → actionLine`이다.
- 결과 계약: 화면에는 확인한 음식, 예상 칼로리 범위와 오차 안내, 안전한 `roastLine`, 서버가 고른 `actionLine`만 표시한다. 정확도 퍼센트와 확정 칼로리는 만들지 않는다.
- 실패와 회복: 음식 아님·사진 불확실·의료 경계는 기존 재촬영 또는 안전 안내로 복구한다. TTS 미지원·음성 없음·재생 실패는 같은 팩폭의 `대사 보기`로 전환한다.
- 가치 뒤 행동: 행동은 localStorage에 저장하고 다음 방문에 복원한다. 다음 사진만으로 실행을 단정하지 않고 사용자가 `해봤어요 / 아직 못 했어요`로 기록한다.

## 정확히 5개 상태

| 단계 | 화면의 이야기 | 실제 UI | 주 CTA | CTA 뒤 상태 |
|---|---|---|---|---|
| 1 사진 제출 | 오늘 한 끼를 숨기지 않고 보여준다 | 사진 선택, 미리보기, 사진 미저장 안내 | 사진 속 음식 확인하기 | Gemini 분석 대기 후 2단계 |
| 2 음식·칼로리 확인 | 혼나기 전에 AI가 본 음식과 칼로리 추정 범위를 확인한다 | 사진, 음식 이름, 예상 kcal 범위, 오차 안내, 다른 사진 고르기 | 맞아요, 음성 팩폭 들을게요 | 3단계 음성 플레이어 |
| 3 음성 팩폭 | 칼로리, 코미디 팩폭, 실제 복귀 조언을 순서대로 듣는다 | 코치 마스코트, 파형, 세 구간 대사, 재생·정지·다시 듣기, 조용히 대사 보기 | 다음 한입 받기 | 4단계 행동 카드 |
| 4 복귀 약속 | 혼남을 작은 행동 하나로 끝낸다 | 한 가지 미션, 다시 듣기 | 이걸로 약속하기 | 행동 저장 후 재방문 준비 |
| 5 복귀 확인 | 다음 끼니에서 약속을 솔직히 기록한다 | 저장 행동, 새 사진, 해봤어요·아직 못 했어요 | 기록하고 다시 혼나기 | 기록 저장 후 새 분석 루프 |

## 음성 UX 경계

- 자동 재생하지 않는다. 첫 재생은 반드시 명시적 탭으로 시작한다.
- 음성 재생 중에는 `멈추기`, 완료 뒤에는 `한 번 더`를 제공한다.
- 회사·대중교통 사용자를 위해 `조용히 대사 보기`를 같은 화면에 둔다.
- 대사는 접근성용 텍스트로도 남기되, 화면의 영웅 요소는 텍스트 카드가 아니라 파형과 재생 상태다.
- 팩폭은 웃음으로 끝내지 않는다. 음성 마지막에는 서버가 고른 구체적인 다음 끼니 행동을 반드시 읽는다.
- 칼로리는 사진 추정 범위임을 말하고, 사용자가 굶거나 보상 운동을 하도록 만들지 않는다.
- 화면을 떠나거나 새 사진을 고르면 재생을 즉시 취소한다.
- 실제 사람·유명인 음성을 흉내 내지 않고 기기 기본 한국어 음성만 사용한다.

## Design Read

- 목적: 사진 전용 팩폭을 음성으로 듣고 다음 한입 하나를 받는다.
- 진입 상태: 식단을 망쳤다는 죄책감은 있지만 기록은 귀찮은 상태
- 인지 순서: 1) 내 사진 2) AI가 본 음식 3) 눌러서 듣는 팩폭 4) 다음 한입 5) 다음 사진에서 확인
- 이탈 감정: 혼났지만 웃겼고, 다음 끼니 하나는 해볼 만하다는 느낌
- 기억 단서: 빨간 확성기·호루라기 마스코트와 음성 파형
- DESIGN_VARIANCE: 7/10 — 3단계만 오디오 포스터처럼 크게, CTA 위치는 일관되게 유지
- MOTION_INTENSITY: 4/10 — 재생 중 파형과 버튼 상태만 움직이고 장면 전환 애니메이션은 쓰지 않음
- VISUAL_DENSITY: 4/10 — 한 화면에 사실·행동 하나씩, 결과 화면도 음성 컨트롤 외 부가 정보 최소화

## 최종 캐릭터 방향

- 20대 후반~30대 초반의 호감형 남성 웹툰 트레이너로 보이게 한다.
- 짧은 검은 머리, 빨간 집업 트레이닝복, 호루라기, 자신감 있는 반웃음을 일관되게 사용한다.
- 작은 화면에서는 상반신 아바타, 음성 팩폭 화면에서는 허리 위 영웅 일러스트로 확장한다.
- 근육 과장, 위협적인 표정, 몸 평가, 원본 레퍼런스의 얼굴·로고·고유 포즈 복제는 금지한다.

## 시각 사전 점검

- 통과: 스마트폰 5개, 1~5 단계, 왼쪽에서 오른쪽 화살표, 동일한 다크 디자인 시스템
- 통과: 3단계만 강한 음성 영웅 장면이며 파형·재생 상태·멈추기·다시 듣기·대사 보기가 보임
- 통과: 사진 입력, 음식 확인, 복귀 행동 저장, 다음 사진과 실행 여부 기록이 현재 계약에서 추적 가능
- 통과: 가짜 칼로리, 신뢰도 퍼센트, 후기, 성과 수치, 결제 완료, 실제 사람 없음
- 통과: 칼로리는 `900~1,150 kcal` 범위와 `양·조리법에 따라 달라져요` 안내로 표시
- 통과: 음성 결과가 `칼로리 → 팩폭 → 코치 조언`으로 구분되고, 코치 조언이 다음 미션과 일치
- 사전 점검 한계: 생성 이미지는 인터랙션과 TTS 동작을 증명하지 않는다. 음성 구현은 별도 craft 단계에서 브라우저·기기별로 검증해야 한다.
