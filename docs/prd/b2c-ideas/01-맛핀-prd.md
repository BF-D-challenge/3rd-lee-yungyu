## 처음 보는 사람을 위한 한 문장

**MATPICK(맛픽)**은 Instagram에서 발견한 맛집 릴스를 `@matpickapp`에 DM으로 공유하면 식당·지역·음식·방문 상황별로 자동 분류해 사용자의 비공개 맛집 지도에 저장하는 모바일 웹 서비스다.

맛픽은 Instagram 저장함 전체를 가져오겠다고 약속하지 않는다. 사용자가 직접 DM으로 보낸 릴스만 정리한다.

## 0-A. 피벗 결정

### 이전 제품

사용자가 YouTube·Instagram·TikTok URL을 웹사이트에 붙여 넣고, 장소를 확인한 뒤 여행 동선을 만드는 개인 맛집 지도.

### 변경한 제품

사용자가 Instagram을 보던 흐름을 떠나지 않고 맛집 릴스를 `@matpickapp`에 DM으로 보내면, 사용자별 지도에 즉시 정리되는 개인 맛집 저장 도구.

### 피벗한 이유

1. 본질 문제는 맛집 추천 부족이 아니라 **저장한 릴스를 필요할 때 다시 찾지 못하는 것**이다.
2. 웹사이트로 이동해 URL을 붙여 넣는 행동은 Instagram의 기존 `공유하기`보다 번거롭다.
3. 공식 Instagram 메시지 웹훅은 보낸 사람의 Instagram-scoped ID와 공유된 릴스 URL을 전달할 수 있어 사용자별 저장함을 만들 수 있다.
4. 공식 API는 일반 사용자의 Instagram 저장함 전체를 가져오는 기능을 제공하지 않는다.
5. 여행 동선·결제·세 플랫폼 지원보다 `공유 → 분류 → 저장 → 재사용` 한 바퀴를 먼저 검증해야 한다.

### 제품 경계

- **댓글**: 맛픽 소유 광고·릴스에서 DM 대화를 시작시키는 유입 장치
- **DM**: 사용자가 릴스를 저장하는 핵심 입력
- **AI와 장소 검색**: 릴스를 장소 정보로 바꾸는 처리
- **모바일 웹**: 사용자별 지도·컬렉션을 확인하고 다시 쓰는 결과 화면
- **로그인**: 첫 결과 이후 기기 변경·복구가 필요할 때 선택적으로 연결

## 0-B. 전체 사용자 여정

### 광고 → 첫 사용 → 결과 → 저장 → 재사용

| 광고 | 첫 사용 | 결과 | 저장 | 재사용 |
|---|---|---|---|---|
| “저장한 맛집 릴스, 다시 찾을 수 있나요?” | 맛픽 광고·릴스에 `맛픽` 댓글 또는 프로필에서 DM 열기 | 비공개 답장으로 “저장할 릴스를 이 대화에 보내주세요” 안내 | 릴스를 DM으로 공유하면 장소·지역·상황을 분류해 개인 저장함에 추가 | DM의 개인 링크로 지도에서 근처 장소를 보고 원본 릴스·외부 길찾기 실행 |

### 핵심 반복 루프

```text
릴스에서 맛집 발견
→ @matpickapp으로 DM 공유
→ “성수역 · 데이트 · 이탈리안으로 저장했어요”
→ 내 맛픽 지도에서 확인
→ 다음 릴스도 다시 DM 공유
```

댓글은 맛픽 계정이 소유한 게시물에서만 안정적인 시작 장치로 사용한다. 다른 사람의 릴스 댓글에 `@matpickapp 저장`을 남기는 방식은 핵심 저장 기능으로 약속하지 않는다.

## 1. 문제 정의 — Phase 2/7

### 표면 문제

Instagram에 맛집 릴스를 많이 저장해도 약속이나 여행 때 어느 릴스에 어느 식당이 있었는지 다시 찾기 어렵다.

### 본질적 문제

Instagram 저장함은 콘텐츠를 다시 보는 목록이지, **장소·지역·메뉴·방문 상황으로 찾아 실제 방문 결정을 내리는 도구가 아니다.**

1. 저장 당시에는 “나중에 가야지”라고 생각하지만 장소 정보를 따로 기록하지 않는다.
2. 저장함이 커질수록 제목·썸네일만으로 원하는 식당을 찾기 어렵다.
3. 방문 시점에는 릴스를 다시 찾고 식당명을 확인한 뒤 지도 앱에서 재검색한다.
4. 이중 탐색이 귀찮아 대부분의 저장 릴스가 방문 행동으로 이어지지 않는다.

> **본질 문제 한 문장:** 맛집 릴스를 발견한 순간과 실제 방문할 장소를 고르는 순간 사이에, 릴스를 검색 가능한 장소 정보로 바꿔주는 개인 정리 도구가 없다.

### 현재 사람들이 푸는 방식

- Instagram 저장함과 컬렉션에 릴스를 쌓아둔다.
- 친구 또는 자기 계정에 DM으로 보내둔다.
- 카카오톡 나에게 보내기나 메모 앱에 URL을 모은다.
- 영상 설명·댓글에서 상호를 찾고 네이버지도·카카오맵에 다시 저장한다.
- 결국 저장한 릴스 대신 지도 검색 결과와 리뷰 앱에서 새로 찾는다.

### 왜 지금인가

- Instagram의 공유 행동은 사용자가 이미 알고 있는 입력 방식이다.
- Meta 메시지 웹훅은 메시지를 보낸 사용자와 공유된 릴스 URL을 구분할 수 있다.
- AI와 국내 장소 검색 API를 조합하면 식당·지점 후보를 만들고 사용자가 한 번 확인하도록 할 수 있다.
- 공개 릴스 메타데이터 수집은 플랫폼·게시물 상태에 따라 실패할 수 있으므로, 자동화가 아니라 **빠른 확인과 복구 흐름**까지 제품으로 설계해야 한다.

## 2. 타겟과 사용자가 원하는 일 — Phase 3/7

### 핵심 사용자

**민지, 29세 직장인**

- Instagram에서 주 3회 이상 맛집·카페 릴스를 저장한다.
- 저장함에 음식 콘텐츠가 50개 이상 쌓여 있다.
- 주말 약속을 정할 때 저장함을 다시 넘기거나 지도 앱에서 새로 검색한다.
- 자신이 믿는 크리에이터가 소개한 장소를 일반 검색 결과보다 우선하고 싶다.
- 새 앱을 설치하거나 릴스 URL을 복사해 다른 웹사이트에 붙여 넣기는 귀찮다.

### 제외하는 초기 사용자

- 맛집 릴스를 거의 저장하지 않는 사람
- 범용 릴스 북마크 도구를 원하는 사람
- YouTube·TikTok까지 한 번에 정리해야만 가치가 있는 사람
- 공개 맛집 랭킹·예약·리뷰 작성을 주목적으로 하는 사람
- 비공개 게시물이나 삭제된 콘텐츠까지 자동 수집되길 기대하는 사람

### 사용자가 원하는 일

> Instagram에서 맛집 릴스를 발견했을 때 앱을 나가지 않고 맛픽에 보내고 싶다. 그래야 나중에 지역·음식·상황으로 찾아 원본 릴스와 실제 장소를 바로 열 수 있다.

### Job Story

When **Instagram에서 나중에 가고 싶은 맛집 릴스를 발견했을 때**,
I want to **공유 한 번으로 장소와 방문 맥락을 내 지도에 남기고**,
so I can **약속을 잡을 때 저장함을 다시 뒤지지 않고 갈 곳을 고를 수 있다**.

### Value Proposition

- **Who**: Instagram에 맛집 릴스를 반복 저장하는 모바일 사용자
- **Why**: 저장은 쉽지만 장소 기준으로 다시 찾고 방문하는 과정은 어렵다.
- **What before**: Instagram 저장함을 뒤지고 지도 앱에서 식당을 다시 검색한다.
- **How**: 릴스를 `@matpickapp`에 DM으로 보내면 사용자별로 장소·지역·음식·상황을 분류한다.
- **What after**: 개인 지도에서 근처 후보와 원본 릴스를 함께 보고 실제 방문 행동으로 이어간다.
- **Alternatives**: Instagram 저장함은 수집에 강하고 지도 앱은 장소 관리에 강하다. 맛픽은 **공유 한 번으로 두 단계를 연결하는 것**에 집중한다.

## 4. 솔루션과 MVP — Phase 5/7

### 솔루션 형태

입력은 Instagram DM, 처리와 저장은 서버, 결과 확인은 모바일 웹으로 나눈다. 사용자는 별도 앱을 설치하지 않는다.

`@matpickapp` 전용 Instagram Professional 계정을 Meta 앱에 연결한다. 개인 운영 계정은 사적 DM과 서비스 데이터가 섞이므로 사용하지 않는다.

### 핵심 가치 한 문장

**Instagram에 맛집 릴스를 저장하는 사람을 위한 개인 지도인데, 릴스를 `@matpickapp`에 보내기만 하면 장소·지역·음식·상황별로 사용자마다 자동 정리된다.**

### Must-have 기능 — 정확히 3개

#### 1. DM 수신과 사용자별 저장함

- Meta 메시지 웹훅으로 새 DM을 받는다.
- `sender.id`의 Instagram-scoped ID를 내부 사용자에 연결한다.
- `share`, `ig_reel`, `reel` 첨부의 공개 URL을 수신한다.
- 메시지 ID와 사용자·URL 조합으로 중복 저장을 막는다.
- 첫 DM 즉시 임시 저장함을 만들며 회원가입을 요구하지 않는다.
- 사용자가 보낸 텍스트·일반 사진 등 지원하지 않는 입력에는 가능한 다음 행동을 답한다.

#### 2. 릴스 분석과 장소 확인

- 공개 릴스 URL에서 설명·작성자·허용된 메타데이터를 가져온다.
- Meta 공식 경로와 공개 메타데이터를 우선하고, RapidAPI는 실패 시 사용하는 교체 가능한 어댑터로 둔다.
- AI가 식당명·지역·음식 종류·방문 상황 후보를 만든다.
- 국내 장소 검색 API로 실제 지점·주소·좌표 후보를 확인한다.
- 확신도가 높으면 저장 결과를 바로 보내고, 낮으면 DM 또는 웹에서 최대 3개 후보 중 고르게 한다.
- 비공개·삭제·접근 불가 릴스는 억지로 추정하지 않고 상호나 지역을 물어 흐름을 복구한다.

#### 3. 개인 지도와 재사용

- 사용자별 비공개 지도에 확인된 장소를 핀으로 보여준다.
- 지역·음식·상황·저장 시점으로 필터링한다.
- 한 장소에 여러 릴스가 있으면 핀 하나에 원본 릴스를 묶는다.
- 핀에서 원본 릴스, 외부 길찾기, 분류 수정, 삭제를 제공한다.
- DM 결과에는 만료되는 개인 링크를 제공하고, 기기 간 보존이 필요할 때만 선택적 로그인을 제안한다.

### 시스템 흐름

```text
Instagram DM
→ Meta webhook
→ 사용자 식별
→ 릴스 URL 정규화·중복 확인
→ 메타데이터 수집
→ AI 장소·태그 후보
→ 국내 POI 매칭
→ 자동 저장 또는 사용자 확인
→ Supabase 사용자별 저장
→ Instagram 결과 메시지
→ 개인 웹 지도
```

### 최소 데이터 구조

| 객체 | 핵심 필드 |
|---|---|
| `instagram_identity` | 내부 사용자 ID, 암호화된 IG-scoped ID, 사용자명, 동의 시각 |
| `message_intake` | 메시지 ID, 사용자, 첨부 유형, 수신 시각, 처리 상태 |
| `reel_source` | 사용자, 원본 URL, 정규화 URL, 작성자, 설명, 공개 접근 상태 |
| `place_candidate` | 상호, 지점, 주소, 좌표, 음식, 상황, 확신도, 근거 |
| `saved_place` | 사용자, 장소 식별자, 연결된 릴스, 사용자 확인 여부, 저장 시각 |
| `magic_session` | 사용자, 해시된 토큰, 만료 시각, 사용 시각 |
| `event` | 사용자, 이벤트명, 대상 ID, 시각, 실패 코드 |

### Demo Flow

1. 사용자가 `@matpickapp` 전용 Instagram 계정에 처음 DM을 보낸다.
2. Instagram에서 맛집 릴스를 `@matpickapp`으로 공유한다.
3. 맛픽이 장소·지역·음식·상황을 분류해 저장 완료 메시지를 보낸다.
4. 애매한 지점 한 건은 사용자가 후보를 골라 바로 수정한다.
5. 사용자가 개인 링크를 열어 지도에서 저장 장소를 보고 외부 길찾기를 실행한다.

### Non-goals

- Instagram 저장함 전체를 로그인·쿠키·비공식 자동화로 가져오지 않는다.
- 다른 사람의 릴스 댓글에서 `@matpickapp 저장`을 감시하는 기능을 핵심 흐름으로 만들지 않는다.
- 범용 릴스 북마크, YouTube·TikTok 입력, 채널 일괄 수집은 이번 MVP에서 만들지 않는다.
- 영상 파일을 다운로드·재호스팅하거나 비공개 콘텐츠 접근을 우회하지 않는다.
- 네이티브 앱, OS 공유 확장, 공개 소셜 피드, 친구 공동 편집을 만들지 않는다.
- 여행 동선·예약·웨이팅·리뷰·결제 기능을 만들지 않는다.

### 디자인 원칙

- **주 디자인은 Google Maps로 잠근다.** 타이포그래피·색·밀도·지도와 하단 시트 구조를 제품 전체에 일관되게 사용한다.
- Beli는 지역 선택과 첫 목록 행동, Collect는 공유 시트에서 수집을 시작하는 행동, Corner는 저장함의 정보 구조만 참고한다.
- 다른 앱의 시각 스타일은 섞지 않는다.
- 첫 화면은 제품 설명보다 `Instagram에서 맛픽으로 릴스를 보내는 방법`을 먼저 보여준다.
- 모든 버튼은 실제 행동이나 명확한 준비 상태로 연결한다.

- 실제 저장함을 보여주거나 릴스 3개 이상을 보낼 수 있는 사람

3. 운영자가 자동화 없이 장소·지역·음식·상황을 분류해 60초 안에 답한다.
4. 참가자별 임시 지도 또는 목록 링크를 만들어 돌려준다.
5. 7일 동안 새 릴스 추가, 지도 재방문, 원본 릴스·길찾기 행동을 관찰한다.
6. 공유 시점과 실패 이유를 인터뷰가 아니라 실제 행동 기록과 함께 남긴다.

| 관찰 결과 | 결정 |
|---|---|
| 10명 중 4명 미만이 릴스 3개를 보냄 | DM 입력 가설 중단. 붙여넣기 웹으로 돌아가지 말고 문제 강도를 재검증 |

| private·deleted·unsupported 비율이 30% 초과 | 릴스 자동 분석 범위와 공급 경로를 재설계하기 전 확장 중단 |
| 사용자 A의 저장 항목이 사용자 B에게 노출되는 오류 1건 | 즉시 중단하고 데이터 격리 수정 전 재개 금지 |

### 정책·데이터 안전 가드레일

- Meta 앱에 연결된 `@matpickapp` 전용 Professional 계정으로만 서비스 DM을 받는다.
- 사용자가 직접 보낸 메시지와 릴스 URL만 처리한다.
- Instagram-scoped ID는 사용자명 대신 내부 키로 쓰되 서버 밖에 노출하지 않는다.
- 개인 웹 링크에는 원본 ID를 넣지 않고 해시된 만료 토큰을 사용한다.
- 서비스 제공에 필요하지 않은 DM 본문과 프로필 정보는 저장하지 않는다.
- 비공개·삭제 콘텐츠 접근을 우회하거나 Instagram 로그인 정보를 요구하지 않는다.
- RapidAPI 공급자는 공개 정보·약관·안정성을 검수하고 언제든 교체할 수 있게 격리한다.
- 사용자는 릴스·장소·전체 계정을 삭제할 수 있어야 한다.

## 6. 주차별 마일스톤 — Phase 7/7

### 1주차: DM 행동을 수동으로 검증

- **목표**: 사용자가 실제 저장 릴스를 반복 전송하고 개인 지도를 다시 여는지 확인한다.
- **산출물**:
  - 적격 사용자 10명과 동의 기록
  - 사용자별 릴스·장소 수동 분류 결과
  - 전송·분류 정확도·D7 재방문 행동표
  - `진행 / 입력 피벗 / 지도 피벗 / 중단` 결정문
- **게이트**: 반복 전송 또는 D7 재방문이 Kill 기준이면 Meta 자동화 구현을 확장하지 않는다.

### 2주차: Meta 웹훅과 사용자 격리

- **목표**: 실제 DM 한 건을 올바른 내부 사용자와 릴스 URL로 저장한다.
- **구현 범위**:
  - `@matpickapp` Professional 계정과 Meta 앱 연결
  - 메시지 웹훅 검증·서명 확인
  - IG-scoped ID 기반 내부 사용자 생성
  - 릴스 첨부 URL 수신·정규화·중복 방지
  - 지원하지 않는 입력 응답
- **산출물**: 서로 다른 두 사용자 간 저장 데이터 격리 테스트와 실제 DM 수신 데모

### 3주차: 장소 분석과 저장 결과

- **목표**: 릴스 URL이 확인 가능한 장소·태그가 되어 사용자 저장함에 들어간다.
- **구현 범위**:
  - 공개 메타데이터·RapidAPI 어댑터
  - AI 분류와 국내 POI 매칭
  - 확신도와 후보 선택
  - 성공·확인·실패 DM 응답
  - 핵심 이벤트 계측
- **산출물**: 실제 릴스 30개의 정확도·응답 시간·보정 횟수 리포트

### 4주차: 개인 지도와 재사용

- **목표**: DM 저장 → 지도 확인 → 원본·길찾기 재사용 한 바퀴를 검증한다.
- **구현 범위**:
  - 만료되는 개인 링크
  - Google Maps 스타일의 개인 지도·하단 장소 시트
  - 지역·음식·상황 필터
  - 원본 릴스·외부 길찾기·수정·삭제
  - 선택적 로그인과 계정 복구 진입
- **산출물**:
  - 모바일 배포 URL

  - 10명 행동 퍼널
  - D7 결과와 다음 버전 결정문

## 7. 최종 검수 체크리스트

### 기능

- [ ] 서로 다른 사용자의 DM이 서로 다른 저장함으로 분리된다.
- [ ] 공유된 릴스 URL과 보낸 사람의 IG-scoped ID를 받는다.
- [ ] 같은 사용자가 같은 릴스를 다시 보내도 중복 핀이 생기지 않는다.
- [ ] 확신도가 낮은 장소는 사용자 확인 없이 저장하지 않는다.
- [ ] 분석 실패 후 식당명 또는 지역 입력으로 복구할 수 있다.
- [ ] 지도에서 원본 릴스와 외부 길찾기를 실행할 수 있다.

### 사용자 경험

- [ ] 첫 릴스의 결과를 보기 전에 회원가입을 요구하지 않는다.
- [ ] 성공·후보 확인·실패 상태마다 다음 행동이 있다.
- [ ] Google Maps의 시각 언어를 전체 제품에 일관되게 사용한다.
- [ ] 댓글은 유입, DM은 저장, 웹은 재사용이라는 역할이 섞이지 않는다.
- [ ] 개인 링크가 만료됐을 때 복구 방법을 안내한다.

### 신뢰·정책

- [ ] `@matpickapp` 전용 Professional 계정만 Meta 앱에 연결한다.
- [ ] 웹훅 서명과 중복 메시지를 검증한다.
- [ ] 사용자 A의 저장 항목이 사용자 B에게 노출되지 않는다.
- [ ] 원본 릴스 URL과 분류 근거가 남는다.
- [ ] 비공개 콘텐츠·저장함 전체·로그인 정보를 우회 수집하지 않는다.
- [ ] RapidAPI가 실패해도 사용자 확인으로 흐름을 끝낼 수 있다.
- [ ] 사용자가 저장 데이터와 계정을 삭제할 수 있다.

### 아직 검증된 사실이 아닌 것

- 사용자가 Instagram 저장 대신 맛픽 DM 공유를 반복한다는 가설
- 실제 릴스 80% 이상에서 올바른 식당 지점을 찾을 수 있다는 가설
- 60초 이하의 자동 응답이 가능한지에 대한 가설
- 개인 지도를 7일 안에 다시 열고 방문 행동으로 이어간다는 가설
- RapidAPI 공급자가 필요한 공개 릴스 정보를 안정적으로 제공한다는 가설

이 항목들은 실제 사용자 행동과 기술 실험이 통과되기 전에는 제품 사실이나 시장 근거로 표현하지 않는다.
