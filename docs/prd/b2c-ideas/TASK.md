## T4. 맛핀 — Meta 수신·Gemini 장소 추출·지도 저장 검증

> 현재 상태: `/matpin` 공개 체험은 고정 샘플 Mock이다. Meta Webhook·Gemini·장소 검색·개인 저장 코드와 운영 전환 플래그는 구현했지만, Meta 승인·운영 비밀값·Supabase 마이그레이션·실제 릴스 종단 간 검증 전까지 자동 저장은 비활성 상태다.
>
> 운영 차단: Meta Professional 계정·메시지 권한·App Review·토큰, Kakao 장소 검색 키, Supabase service role과 마이그레이션 적용이 필요하다. 현재 로컬에는 Docker/Podman이 없어 새 SQL의 실제 적용 검증도 남아 있다.
>
> 구현 순서: `Meta 릴스·DM 수신 → 입력 검증·사용자 구분 → Gemini 장소 후보 추출 → 실제 장소 확인 → 개인 지도 저장 → 결과 답장`
>
> 운영 원칙: Instagram URL만 Gemini에 바로 넘기지 않는다. Meta가 전달한 접근 가능한 첨부 URL·메타데이터 또는 허용된 영상 파일을 확보한 뒤 분석한다.

### 0. 코드 없는 수요 검증

- [ ] 최근 한 달 맛집 릴스를 10개 이상 저장한 성인 10명 모집
- [ ] 참가자가 실제 릴스 3개 이상을 `matpin.kr` Instagram 계정에 공유
- [ ] 운영자가 60초 안에 장소 후보를 찾아 성공·후보 확인·실패 답장을 수동 전송
- [ ] 사용자별 개인 지도 링크를 전달하고 다른 사용자의 장소가 보이지 않는지 확인
- [ ] 일주일 동안 새 릴스 전송, 지도 재방문, 원본 릴스 열기, 외부 길찾기 측정
- [ ] 10명 중 6명 이상이 릴스 3개 이상을 보내고 4명 이상이 7일 안에 지도를 다시 열었을 때만 자동화 진행

### 1. Meta 릴스·DM 수신

- [ ] `matpin.kr` Instagram Professional 계정과 Meta 앱 연결
- [ ] 메시지 수신에 필요한 권한, App Review, 액세스 토큰 발급 조건 확인
- [x] Webhook 검증 요청과 메시지 이벤트 수신 엔드포인트 구현
- [x] Webhook 서명 검증, 재전송 방지, 이벤트 ID 기준 중복 처리 방지 구현
- [x] 발신자 Instagram-scoped ID, 메시지 ID, 첨부 유형(`share`·`ig_reel`·`reel`), 첨부 URL을 내부 입력 계약으로 정규화
- [x] DM 본문·프로필 등 장소 저장에 불필요한 개인정보는 수집하지 않도록 제한
- [x] Meta 비밀값과 액세스 토큰은 서버 환경 변수로만 관리하고 로그에서 마스킹
- [ ] 서로 다른 실제 계정 2개로 릴스를 공유해 수신과 사용자 분리가 되는지 확인

#### Gate A — Meta 입력 확보

- [ ] 공개·비공개·삭제된 릴스 샘플로 Meta가 실제 분석 가능한 첨부 URL 또는 영상 데이터를 주는지 확인
- [ ] 분석 가능한 원본을 확보하지 못하면 Gemini 연결을 보류하고 수동 후보 확인 흐름을 유지
- [ ] 미지원·접근 불가 입력 비율이 30%를 넘으면 자동 저장 범위 또는 채널을 다시 결정

### 2. Gemini 장소 후보 추출

- [x] 기존 Shorts 분석 코드와 분리된 `ReelAnalyzer` 계약 정의
- [x] `MockReelAnalyzer`와 `GeminiReelAnalyzer`를 같은 응답 형식으로 구현

- [x] Gemini에는 원본 DM 문장이나 사용자 프로필 대신 필요한 영상·최소 메타데이터만 전달

- [x] `GEMINI_API_KEY`가 없거나 호출이 실패하면 가짜 성공 대신 명시적 실패·확인 안내 반환
- [x] 맛핀 전용 모델 환경 변수와 기능 플래그를 두고 운영 전환 전까지 기본값을 Mock으로 유지

- [ ] 최고점 후보 하나와 선택 이유를 5문장으로 기록
- [ ] 선택하지 않은 네 후보는 `보류`로 표시하고 구현하지 않음

완료 산출물: 후보 비교표, 선택 근거, 구현할 PRD 한 개.
