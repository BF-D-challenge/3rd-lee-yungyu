# 4개 앱 전체 디자인·제품 계약 감사

작성일: 2026-07-28
범위: Root Hub, MATPICK, 한입코치, Today, 상황 카드

## 결론

화면의 가장 큰 문제는 색이나 카드 모양이 아니었다. 앱마다 “저장”, “제작 중”, “이어서 보기”가 실제 제공 범위보다 강하게 표현됐고, 44px·48px 터치 기준과 반응형 기준도 섞여 있었다.

이번 개선은 다음 순서로 적용했다.

1. 화면의 약속과 실제 API·로컬 저장 범위를 일치시킨다.
2. 첫 결과 전 가입을 요구하지 않는다.
3. 모든 주요 버튼은 실제 행동이나 목적지를 가진다.
4. 공통 터치, 포커스, 본문 행간, 반응형 기준을 맞춘다.
5. 앱마다 이미 검증된 고유한 시각 정체성은 유지한다.

## 심층 진단과 적용

### 1. Hub

문제:

- 4개 앱이 데스크톱에서 3+1로 배치되어 마지막 앱이 중요도가 낮아 보였다.
- 최근 앱 문구가 결과 복원을 암시했지만 실제로 저장된 것은 경로뿐이었다.
- Today도 다른 앱처럼 “바로 받는 결과”로 표현되어 24시간 공개 조건이 흐려졌다.

적용:

- 600px 이상 2열, 840px 이상도 2×2를 유지한다.
- “이어서 열기”를 “다시 열기”로 바꾸고 입력 화면 복귀라고 명시한다.
- 공통 라벨을 “받는 결과”로 바꾸고 Today는 “24시간 뒤”를 출력 문구에 포함한다.
- 오래된 `/matpick/map` 최근 경로도 대표 `/matpick`으로 복구한다.

### 2. MATPICK

문제:

- 화면은 “내 Instagram 수집함”처럼 보이지만 현재 데이터는 공개 원본 기반 사전 샘플이다.
- 현재 위치 재조회 시 API 응답이 로컬 Shorts 추가 장소를 덮어썼다.
- `/matpick`과 `/matpick/map`이 같은 화면을 중복 제공했다.
- 지도 칩·핀·상단 버튼 다수가 44px였고, 일부 출처 문구는 10px였다.

적용:

- “사전 수집한 공개 원본”, “Instagram DM 자동 수집 전”을 첫 목록 영역에 표시한다.
- 현재 위치 재조회 뒤에도 로컬 추가 장소를 새 origin 거리로 다시 계산해 합친다.
- 대표 주소를 `/matpick`으로 통일하고 이전 주소는 영구 이동한다.
- 주요 조작은 48px로, 보조 출처 글자는 최소 11px로 높였다.
- filter group, 선택된 marker·list row에 실제 접근성 선택 상태를 제공한다.
- reduced-motion에서는 지도 로더 회전을 완전히 멈춘다.

남은 제품 작업:

- Instagram DM Webhook → 사용자 식별 → 후보 확인 → 개인 지도 저장 API가 필요하다.
- 현재 웹 MVP의 Shorts 직접 추가는 보조 실험으로 유지하며 Instagram 자동 수집이라고 부르지 않는다.

### 3. 한입코치

문제:

- 저장 완료 뒤 재방문하면 행동 문장이 보이지 않았다.
- “다음 끼니 행동”이라는 제품 약속과 다음 사용의 연결이 끊겼다.

적용:

- 저장값에 action code뿐 아니라 행동 문장과 시간을 함께 남긴다.
- 다시 열면 지난 행동을 먼저 보여주고, 아래에서 다음 끼니 사진을 골라 새 행동으로 이어지게 한다.
- 저장 삭제는 별도 48px 행동으로 제공한다.
- 840px에서 확장형 2열 레이아웃으로 통일한다.
- 고대비 모드에서 카드·업로드 경계를 강화한다.

남은 제품 작업:

- 다음 사진이 지난 행동의 실행 여부를 보여주는지 비교하는 계약은 아직 없다.
- 계정 연결은 결과·사진 동기화를 제공하지 않으므로 현재 문구처럼 “계정만 연결”로 한정한다.

### 4. Today

문제:

- 신청 순간 결과물이 이미 생성되지만 “제작 진행 중”으로 표현되어 실제 작업 큐처럼 보였다.
- 결과 카드와 전체 화면의 fake-door CTA가 죽은 버튼이었다.
- 이메일 오류가 입력과 명시적으로 연결되지 않았다.

적용:

- 상태를 “24시간 공개 대기 · 로컬 데모”와 “결과 잠금”으로 바꿨다.
- 시작 화면과 신청 화면에서 브라우저 로컬 저장·메일 미발송을 알린다.
- 카드 안 CTA는 미리보기 모양의 비상호작용 요소로 바꾼다.
- 전체 화면 CTA는 클릭 시 job별 수요 행동을 로컬에 기록하고 완료 피드백을 보여준다.
- 이메일 오류와 도움말을 `aria-describedby`로 연결한다.
- hover는 정밀 포인터에서만, keyboard focus는 파란 상태 링으로 통일한다.

남은 제품 작업:

- 실제 24시간 제작 운영을 시작할 때 서버 DB, 작업 큐, 제작자 상태, 메일 알림을 같은 API 계약에 연결해야 한다.

### 5. 상황 카드

문제:

- 핵심 덱 경험은 좋지만 보조 문구가 11px 이하로 작았다.
- 672px·960px 기준이 다른 앱의 600px·840px 기준과 달랐다.

적용:

- 덱과 채팅의 작은 한국어 라벨을 12px 수준으로 높인다.
- medium은 600px, expanded는 840px에서 전환한다.
- 선택 카드와 빠른 답장, composer의 focus·touch·reduced-motion 상태를 유지한다.
- 사용자가 선호한 카드 덱 뽑기와 즉시 채팅 구조는 바꾸지 않는다.

남은 시각 작업:

- 덱에서 선택된 카드가 채팅의 context card로 이어지는 shared-object handoff를 더 선명하게 만들 수 있다. 기능보다 낮은 우선순위다.

## 공통 시스템 결정

### Material 3

- compact: 0–599px
- medium: 600–839px
- expanded: 840px 이상
- 주요 터치 목표: 48×48px
- keyboard focus: 전체 컨트롤에 보이는 3px 상태 링
- 오류: 입력 아래 supporting text로 유지
- 선택: 카드·행 전체에 선택 상태 적용

참고:

- <https://m3.material.io/foundations/layout/layout-overview/overview>
- <https://m3.material.io/foundations/layout/canonical-examples/overview>
- <https://m3.material.io/foundations/designing/structure>
- <https://m3.material.io/foundations/interaction/states/applying-states>
- <https://m3.material.io/components/text-fields/specs>

### Astryx

`@astryxdesign/cli template --list`로 현재 템플릿을 확인했다. Form, AppShell Content Only, Banner, Card/Grid 패턴은 현재 구조와 맞지만, 프로젝트에 `@astryxdesign/core`가 없어 컴포넌트 API 조회는 불가능했다.

결정:

- adopt: content-only shell, helper/error text, persistent status banner의 정보 구조
- adapt: 기존 Next.js·CSS module 구성 안에서 같은 상태 원칙 적용
- reject: 발표 직전 신규 디자인 시스템 의존성 설치와 전면 마이그레이션

### Motion gate

- 유지: 상황 카드 뽑기, 로딩 상태
- 축소: 일반 카드 hover 이동은 정밀 포인터에서만
- 제거: reduced-motion의 spinner와 active scale
- 금지: 기능 변화가 없는 장식용 장시간 애니메이션

## 검증 기준

- 390px compact, 700px medium, 1280px expanded
- 200% 확대 시 가로 스크롤 없음
- keyboard only로 모든 주요 행동 도달
- reduced-motion에서 반복 회전·이동 없음
- 각 버튼에 실제 handler, submit, link 목적지, 또는 명시적 disabled 상태
- 타입 검사, 단위 테스트, 핵심 E2E, production build 통과

## 참고하지 않은 범위

이번 단계에서는 Mobbin을 다시 검색하지 않았다. 가입 시점과 첫 가치 흐름은 기존 Mobbin 결정 문서에 이미 잠겨 있고, 이번 문제는 새 레퍼런스 선택이 아니라 코드의 제품 약속·상태·접근성 불일치였기 때문이다.
