# MVP 앱 재설계 레퍼런스 요약

결론: 각 앱의 첫 화면은 설명과 선택지를 늘어놓기보다 `상황 선택 → 한 번의 핵심 입력 → 바로 결과·대화`로 이어지고, 나머지 도구는 필요할 때만 펼쳐야 한다.

## Pi — Home chat

- 흐름: 상황을 문장으로 입력 → 같은 화면에서 맥락을 반영한 질문과 답변을 이어감
- 관찰: 첫 입력창과 대화가 같은 화면에 있고, 사용자의 첫 문장이 이후 답변과 후속 질문의 맥락으로 남는다.
- 적용: 랜덤 카드는 카드에서 상황 하나를 고르는 즉시 그 문장을 첫 맥락으로 전달하고 채팅 화면을 연다.
- 제외: 카드를 고른 뒤 별도의 설명·확인 화면이나 다시 입력하는 단계를 넣지 않는다.
- 출처: [Mobbin flow](https://mobbin.com/flows/3633dacc-a527-49eb-b898-c410e2b2ce26)

## Lovi — Scanning a product

- 흐름: 분석 대상 선택 → 촬영·업로드 입력 → 한 줄 판정과 근거가 있는 결과
- 관찰: 입력 방식은 시작 시점에 두 개로 제한하고, 결과 화면은 적합도 한 줄과 세 가지 근거, 재실행 액션을 한 화면에 모은다.
- 적용: 분석형 앱은 첫 화면에서 입력 하나를 시작하게 하고, 결과에서는 핵심 판정·근거·다시 해보기 순서만 남긴다.
- 제외: 결과보다 구매 링크·가격·보조 아이콘을 더 강하게 보여주지 않는다.
- 출처: [Mobbin flow](https://mobbin.com/flows/12e8692d-5da8-40a3-a51d-a48d2d39fa8a)

## Flo — Single-question input

- 관찰: 질문 하나, 입력창 하나, 조건 충족 전 비활성인 `Continue`, 상단 `Skip`만 보여줘 현재 할 일을 좁힌다.
- 적용: 초기 설정과 취향 입력은 한 화면에 한 질문만 보여주고, 답변 뒤에만 다음 행동을 활성화한다.
- 제외: 여러 질문·도움말·완료 후 기능 소개를 같은 화면에 쌓지 않는다.
- 출처: [Mobbin screen](https://mobbin.com/screens/a8f2b86d-154c-4bcd-835a-069e3cdfe6f1)

## ChatGPT — Tools chooser

- 관찰: 핵심 화면을 유지한 채 바텀시트에서 네 가지 도구를 아이콘과 동사형 라벨의 한 줄 메뉴로 보여준다.
- 적용: 앱별 보조 기능은 첫 화면의 경쟁 CTA가 아니라, 사용자가 요청했을 때 열리는 시트에 행동 중심 문구로 묶는다.
- 제외: 보조 기능마다 큰 카드와 설명을 만들거나 도구 선택 자체를 별도 랜딩 화면으로 만들지 않는다.
- 출처: [Mobbin screen](https://mobbin.com/screens/8a129430-1bb4-441a-93d1-123b5d334080)

## 우리 앱에 적용

1. 랜덤 카드의 기본 여정은 `카드 덱에서 상황 선택 → 선택 카드가 채팅의 첫 맥락으로 이동 → 바로 대화 시작`으로 고정한다.
2. 분석·생성 앱은 입력 방식을 먼저 하나 고르게 하고, 결과에서는 판정·근거·다음 행동만 남긴다.
3. 온보딩은 한 화면 한 질문, 보조 기능은 바텀시트로 점진적으로 공개한다.
4. 기존 Tinder·Gas 캐시에서 확인한 `한 순간에 한 결정`과 `카드 표면 자체를 버튼으로 사용` 원칙을 카드 선택에만 보조 적용한다.

> 화면 구조는 참고 근거이며 성과 개선을 보장하지 않는다.
