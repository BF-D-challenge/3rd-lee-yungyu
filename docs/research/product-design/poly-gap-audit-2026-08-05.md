# 맛핀과 Poly의 완성도 격차 감사

- 감사일: 2026-08-05
- 범위: 맛핀 스토리보드 선택실의 시각 결과와 Poly 랜딩의 히어로·분산·입력·정리 장면
- 사용자 목표: 모바일 첫 방문자가 `릴스를 보내면 역별 영상 보관함으로 정리된다`를 한 번에 이해하고 기억한다.
- 근거: 이번 감사에서 직접 캡처하고 다시 연 화면만 사용했다.

## 전체 판단

맛핀 후보가 약한 이유는 각도의 수가 부족해서가 아니다. 현재 화면은 **완성된 랜딩을 보여주는 무대가 아니라 24개 모바일 목업을 동시에 평가하는 제작 도구**다. 같은 CSS 재료와 같은 휴대폰 틀을 유지한 채 크롭·회전·accent만 바꿨기 때문에, 후보가 달라도 하나의 템플릿 변형으로 읽힌다.

Poly의 품질은 3D 효과 하나에서 나오지 않는다. 하나의 세계, 하나의 카메라, 같은 오브젝트, 물리적으로 이어지는 이동, 장면마다 하나만 남기는 정보 위계가 함께 작동한다.

## Step 1. 현재 맛핀 — 구조는 정상, 랜딩 아트 디렉션은 약함

![현재 맛핀 스토리보드](/Users/yungyulee/Project/03_BFD/3rd-lee-yungyu/docs/research/product-design/poly-gap-audit-2026-08-05/01-matpin-current.png)

건강도: 비교 도구로는 보통 / 최종 랜딩 기준으로는 낮음

- 네 장면과 평가 행동은 이해할 수 있다.
- 그러나 같은 크기의 휴대폰 4대, 같은 음식 표지, 같은 검정 배경, 같은 얇은 선이 장면마다 반복된다.
- 각 장면이 시간의 한 순간이 아니라 작은 UI 설명판으로 보인다.
- 하단 라운드 바가 시각 무대를 가리고, 화면 안의 작은 글자와 가짜 상태바가 주의를 분산한다.
- 반복된 CSS 카드에는 재질, 광원, 무게, 초점 변화가 없어 3D 공간이 아니라 2D 목업 배열로 읽힌다.

## 격차의 원인

| 기준 | 현재 맛핀 | Poly |
|---|---|---|
| 화면의 정체 | 6개 후보를 평가하는 보드 | 제품 세계를 체험하는 한 무대 |
| 장면 수용량 | 24개 화면을 동시에 제시 | 한 순간에 메시지 하나 |
| 오브젝트 | 같은 휴대폰과 음식 이미지 반복 | 종류·크기·재질이 다른 파일 오브젝트 |
| 시간 연결 | 네 개 스크린샷을 나열 | 같은 카메라와 오브젝트가 연속 변화 |
| 공간 | 검정 CSS 배경 | 광원·그림자·초점이 있는 일관된 세계 |
| 제품 증거 | 작은 합성 UI | 실제 제품 화면을 중심 오브젝트로 사용 |
| 기억 단서 | accent 색과 구도 라벨 | 노트북, 파일 세계, 검색창 |

## 맛핀에 맞는 하나의 방향

### 세계

`어두운 디지털 릴스 아카이브`. 책상 사진은 사용하지 않는다. 중앙의 실제 3D 휴대폰이 Poly의 노트북 역할을 하고, 릴스는 종이 카드가 아니라 빛나는 세로 필름 오브젝트로 존재한다.

### 전체 타임라인

1. **조용한 히어로** — 휴대폰 한 대에서 맛집 릴스를 보는 상태. 제목은 `릴스를 보내면, 역별로 정리돼요.`
2. **화면 안으로 진입** — 카메라가 휴대폰 화면을 지나 디지털 세계로 들어간다.
3. **흩어진 릴스** — 크기·거리·재생 시점이 다른 릴스 8~12개가 깊이별로 떠 있다.
4. **보내기** — 사용자가 고른 한 릴스만 중앙에 고정되고 `matpin.kr` 전송 신호가 닿는다.
5. **단서 정리** — 같은 릴스에서 캡션·작성자 댓글·영상 단서가 분리되어 한 장소 정보로 접힌다.
6. **역별 보관함** — 카메라가 뒤로 빠지면 여러 릴스가 `역삼역·성수역·을지로3가역` 레일로 정렬된다.
7. **제품 증거** — 역삼역 화면을 크게 보여주고 `Instagram에서 matpin.kr 열기` CTA로 끝낸다.

첫 화면은 흩어진 릴스로 시작하지 않는다. Poly처럼 제품 약속과 중심 기기를 먼저 보여주고, 혼란은 두 번째 세계에서 시작한다.

## 권장 제작 방식

**고정 키프레임 7장 → 프리렌더 3D 영상 → DOM 카피와 CTA**의 혼합 방식이 가장 적합하다.

- Blender 또는 Cinema 4D에서 휴대폰, 릴스 카드, 카메라, 광원, 그림자, 심도를 한 장면으로 제작한다.
- 먼저 7개 고정 키프레임을 완성해 미술 방향을 승인한다. 장면 전환부터 코딩하지 않는다.
- 승인 뒤 8~12초 세로 영상을 프리렌더하고 스크롤 진행률에 맞춰 재생한다.
- 제목, CTA, 개인정보 문구, 실제 제품 UI는 React DOM으로 유지한다.
- 모바일에서는 프리렌더 영상으로 안정적인 품질을 내고, reduced-motion에서는 7개 키프레임을 정적인 문서로 보여준다.
- Three.js 실시간 3D는 키프레임의 광원·카메라·재질이 승인된 뒤에만 검토한다.

## 반드시 중단할 것

- 여섯 후보를 동시에 조금씩 고치는 방식
- CSS로 만든 휴대폰·3D 카드·상태바를 최종 자산으로 사용하는 것
- 같은 음식 이미지 네 장을 반복해 세계를 채우는 것
- 모든 장면에 캡션·배지·선·버튼을 동시에 놓는 것
- Mobbin 레퍼런스를 여러 개 평균 내 한 화면에 섞는 것

## 접근성·검증 한계

- Poly의 스크롤 고정과 큰 카메라 이동은 키보드·멀미 방지·reduced-motion 위험이 있다. 높은 시각 완성도와 별개로 그대로 복제하지 않는다.
- 현재 감사는 데스크톱 1280×720 화면을 기준으로 했다. 모바일 키프레임은 별도 동일 뷰포트 비교가 필요하다.
- 스크린샷만으로 키보드, 스크린리더, 프레임 드롭, 실제 모바일 GPU 성능을 확인할 수 없다.

## 다음 결정

다음 구현은 기존 6개 후보를 더 다듬는 것이 아니라, 위 타임라인의 **1번 히어로 키프레임 한 장**을 실제 3D·이미지 자산으로 먼저 완성하는 것이다. 첫 장의 카메라, 광원, 휴대폰, 릴스 표지, 타이포가 승인되기 전에는 2~7번으로 넘어가지 않는다.
